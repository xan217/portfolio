How I approach QA

Four working principles, and what each one looks like in practice.

01

Assess before you build

When I took over an existing automation project at zinc.tech, the first deliverable was not a test. It was an assessment of whether the project could be extended at all, and a technical roadmap for a version that could scale. Everything built after that followed the roadmap.

02

Process first, automation second

Automation only speeds up what a team already does well. At Tenant Evaluation I started by mapping every process of the system under test as diagrams and defining how testing is identified, planned and tracked. With that map in place I wrote more than 130 test cases in the first week, then built automation prototypes for the repetitive work.

03

Test data is part of the product

A suite is only as good as the data it runs on. I split the zinc.tech suite into a data-driven track and an end-to-end track, and built a generator that produces large datasets and bulk-loads them into the platform, so the tests run against realistic volume.

04

A developer's eye on every defect

Years of full-stack work mean I don't stop at the bug report. I trace failures across processes and data layers, and when the fix is mine to make I deliver it, so the suite keeps running reliably instead of piling up known failures.

Personal product, evolving since 2015

Modularity

A multi-company ERP for small businesses that are not run by IT professionals. It started in 2015 as an ERP for a concrete producer and has grown, version by version, into a platform where one core adapts to cafés, auto repair shops, salons and clinics by switching modules on and off and mapping generic entities to each industry's own words: a table, a vehicle, a client or a patient; a waiter, a technician, a stylist or a nurse.

Nine core modules, from orders, scheduling and inventory to production queues and billing, run on fifteen Django microservices behind an nginx gateway. The Angular 20 frontend speaks English and Spanish, renders by role for six user roles, and authenticates with JWT.

It is also where I practice what I preach: Playwright end-to-end and API suites built on page objects, and a Claude Code workflow with seven specialised agents for Django, Angular, database design, Playwright testing, security audits and code review, plus a pre-commit security hook.
